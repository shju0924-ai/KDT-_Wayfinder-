# E2E 회귀 페르소나

`python -m scripts.e2e_eval --set <세트>`가 이 폴더의 `personas.json`을 읽고, `ui` 세트는 `frontend/src/mock/examples.json`을 읽습니다.
불러올 때 모든 페르소나가 아래 규칙으로 검증되고, CI에서도 `tests/test_personas.py`가 같은 검사를 합니다.

| 세트 | 경로 | 목적 |
|---|---|---|
| `v1` | 설문 4명 | 최초 튜닝 기준 |
| `v2` | 설문 3명 + 이력서 1명 | v1에 맞춘 조정이 다른 경력에서도 통하는지(과적합 점검) |
| `resume` | 이력서 원문 4명 | 직무명 입력 없이 이력서만 들어오는 경로 |
| `ui` | 시작 화면 예시 3개 | 화면에 내건 예시가 실제로 끝까지 잘 도는지 |
| `all` | 위 전부 | |

여러 세트는 쉼표로 고릅니다(`--set resume,ui`). `--json` 결과는 페르소나가 끝날 때마다 저장돼, 중간에 멈춰도 끝난 결과는 남습니다.

## 공통 규칙

- 키는 영문 소문자·숫자·`_`만 쓰고, 세트끼리 겹치지 않아야 합니다(`--set all`에서 덮어써짐).
- `_`로 시작하는 키(예: `_case`)는 사람이 읽는 메모입니다. API로 보내지 않습니다.
- 실존 인물·회사의 개인정보는 쓰지 않습니다. 회사명은 `○○은행`처럼 가립니다.

## 설문형 — v2 기준

실제 설문 화면(`SurveyForm.tsx`)이 보낼 수 있는 값만 씁니다. 자유 문구로 쓰면 실제 사용자 입력과 분포가 달라져, 회귀 결과가 화면 경로를 대표하지 못합니다.

- `strengths`: `app/services/survey.py`의 `STRENGTH_OPTIONS`에서 1개 이상 고릅니다.
  (고객 응대 · 문제 해결 · 문서·데이터 관리 · 협업·조율 · 운영 개선 · 현장 대응)
- `years`: `YEAR_OPTIONS` 중 하나 (1년 미만 · 1~3년 · 3년 이상 · 5년 이상 · 10년 이상).
- `experience`: 상황·행동·결과(가능하면 수치)가 들어간 2~3문장.
- `concern`: 자유 문구도 됩니다. 현재 세트는 직무별 AI 영향을 드러내려고 자유 문구를 씁니다.
- `aspiration`: 비워두는(`null`) 페르소나도 섞어서, 희망이 없을 때의 경로도 점검합니다.

선택지를 바꾸면 `survey.py`와 `SurveyForm.tsx`를 함께 고치세요. 기존 페르소나 중 선택지에서 벗어나는 것이 생기면 검증이 실패합니다.

## 이력서형 — 작성 기준

`raw_text` 하나만 둡니다. 새로 추가할 때는 이미 있는 페르소나와 **다른 축**을 하나 이상 다루고, 그 축을 `_case`에 적습니다.

| 축 | 점검하는 것 | 예 |
|---|---|---|
| 형식 | 정형 이력서(섹션·기간) / 자기소개서형 문단 / 개조식 요약 | `bank_teller`, `translator`, `web_publisher` |
| 정보량 | 짧고 빈약한 이력서에서 역량을 부풀리거나 지어내지 않는지 | `retail_sparse` |
| 잡음 | 학력·자격증·교육 칸이 역량 목록에 그대로 들어가지 않는지 | `bank_teller` |
| 경력 수 | 경력이 여럿일 때 가장 최근 직무를 현재 직무로 잡는지 | `career_change` |
| 직무명 위치 | 머리말 없이 문장 속에만 직무명이 있을 때 추출되는지 | `translator` |
| 직군 | 사무·대면·현장·전문직 중 아직 적은 쪽 | |

이력서형 결과에서 볼 것:
- `current_job`이 이력서의 (가장 최근) 직무와 맞는지
- 역량의 `evidence`가 원문에 있는 내용인지(자격증명·학력이 역량으로 나오지 않는지)
- 빈약한 이력서에서 역량 수가 과하지 않은지, 진단 `confidence`가 낮게 나오는지
