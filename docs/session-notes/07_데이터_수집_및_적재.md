# Wayfinder — "데이터 수집 및 적재" 세션

> ⚠️ 이 세션은 총 1,071개 메시지로 매우 깁니다. 아래는 도구가 한 번에 반환 가능한 **최근 500개 메시지 분량**만 정리한 것이며, 그 이전 절반가량(전반부)은 포함되지 않았습니다. 전체가 필요하면 알려주세요 — 이어서 가져올 수 있습니다.

---

## 파트 A — E2E 파이프라인 첫 실제 테스트 (전반부 끝자락)

브라우저로 설문 제출 → LLM 역량 분해 → 벡터 매칭까지 전체 흐름을 실제로 구동하며 검증.

**과정에서 겪고 고친 버그**:
1. **uvicorn `--reload` 감시 범위 문제** — 프로젝트 루트 전체를 감시해서 새로 만든 `data-pipeline/.venv`(수천 개 패키지 파일)까지 변경으로 인식, 요청 처리 중 서버가 재시작되며 `/api/profile` 502 발생. `.claude/launch.json`에서 `--reload-dir backend/app`로 범위를 좁혀 해결.
2. **`OPENAI_API_KEY` 누락** — demo 커밋에서 LLM을 OpenAI로 전환했는데 로컬 `.env`가 갱신 안 됨. 사용자가 키 입력 후 재시작.
3. **`backend/app/core/config.py`의 진짜 버그** — `env_file=".env"`가 프로세스의 현재 작업 디렉터리 기준으로 해석되는데, 리포지토리 루트에서 백엔드를 띄우면 존재하지 않는 `Wayfinder/.env`를 찾음. `DATABASE_URL`은 기본값이 우연히 같아서 안 걸렸지만 `OPENAI_API_KEY`는 빈 문자열이라 조용히 실패. `Path(__file__)` 기준 절대경로로 수정 — **팀원 누구에게나 재현 가능한 버그라 커밋 권장** 표시.

**검증 결과**: 설문 제출 → LLM 역량 분해(근거 포함) → 확정 → 방향 선택 → 실제 DB 채용공고(굿위코리아·한빛데이타·한나케어 등 실명) 벡터 매칭 → 적합도·보유역량·부족역량까지 전체 흐름 정상 동작 확인.

당시 DB 상태: 채용공고 7,908건, 훈련과정 5,000건, NCS 능력단위 15,520건, 자동화 위험도 참고자료 3,297건, 임베딩 1,024차원.

커밋은 하지 않은 상태로 파트 A 종료.

## 파트 B — 전량 재수집 + 만료 데이터 필터링

**사용자 요청**:
1. 채용공고와 HRD 직업 교육에 대한 수집을 다 할 것.
2. 이미 시작한 교육, 모집이 마감된 교육 및 공고를 다시 확인할 것.

**진단**: 기존 수집기는 데모 상한(5,000건)만 받고 마감·개강 필터가 전혀 없었음.
- 경기 채용공고: 5,000건 중 **4,725건이 이미 마감**(유효 275건뿐)
- HRD 훈련과정: 5,000건 **전부 이미 개강**, 그중 4,285건은 종료까지 됨
- 서울: 대부분 미래 마감일이라 상대적으로 양호

**API 전체 규모 확인**: 서울 24,897 · 경기 170,556 · HRD(오늘 이후 개강) 139,329건.

**결정 사항**:
- 채용공고: 서울·경기 전량 수집 → 마감 지난 공고 제외 → 열린 공고만 임베딩
- HRD: 수집 날짜 창을 **오늘 이후**로 변경(API 단계에서 이미 시작한 교육 제외) + 접수 가능(정원 미달)만 유지, 임베딩 실현성 위해 상한(오늘~+90일, 4만 건)
- DB: 기존 만료 데이터가 upsert로는 안 지워지므로 **TRUNCATE 후 재적재**

**구현**: [collectors/filters.py](data-pipeline/collectors/filters.py) 신설(공통 필터), 서울·경기·HRD 세 수집기에 마감/개강 필터 적용, 임베딩 스크립트에 `--fresh`(truncate) 플래그 추가.

**전량 수집 실행 결과**: 서울 24,897→17,645건 열림, 경기 170,556→76,926건 열림, HRD 40,000 수집→10,621건(정리 후).

**임베딩 중 발생한 문제**: 94,571건 임베딩 도중 **Upstage 429 Too Many Requests**로 전체 실패(재시도 로직 없었음). `embed_passages`에 지수 백오프 재시도 + 배치 간 페이싱(`EMBED_INTER_BATCH_SLEEP`) 추가 후 재실행 → 94,571건 전량 성공(약 17분).

**적재 후 발견한 이상치**: 94,571건 시도했는데 최종 **24,329건만 저장**. 원인 추적 결과 — 경기(GG) API 응답 자체에 동일 공고가 페이지마다 **최대 69번씩 중복 응답**되는 페이지네이션 결함 발견(76,926→실제 고유 6,684건). `source_id` 해시 기반 dedup이 정상적으로 이를 걸러낸 것이라 **버그 아님**으로 결론.

**성능 개선**: 94k 규모에서 브루트포스 벡터 스캔이 2.7~2.8초 걸림 → pgvector 0.8.6의 HNSW 인덱스 추가 → 실제 백엔드 쿼리 패턴 기준 **2,750ms → 79ms**로 개선.

**최종 DB 상태**:
```
job_postings      24,329건  (서울 17,645 + 경기 6,684, 전부 마감 안 지남)
training_courses  10,621건  (전부 오늘 이후 개강, 접수 가능)
```

**변경 파일 요약**:
- [collectors/filters.py](data-pipeline/collectors/filters.py) — 신규, 마감/개강 공통 필터
- 서울·경기·HRD 수집기 3개 — 전량 수집 + 필터 적용
- 임베딩 스크립트(embed_jobs, embed_courses) — `--fresh` 플래그, 재시도/백오프, 배치 페이싱
- DB DDL — HNSW 인덱스 추가
- `data-pipeline/README.md` — 새 수집·필터 동작 문서화

이후 background로 4개 셸 명령이 이전 세션에서 정리 안 된 채 남아있었다는 알림이 있었음(orphan, stopped 처리).
