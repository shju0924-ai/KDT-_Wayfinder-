# Wayfinder — "LLM 이미지 수정" 세션 (2026-08-07)

기존에 있던 파이프라인 설명 이미지를 실제 코드 구조에 맞게 재검토하고, 새 인포그래픽 생성을 위한 프롬프트를 만든 세션.

---

**사용자**: 이게 분석 LLM 부분인데 지금 코드를 기반으로 이미지를 재구성 해줘

**어시스턴트**: 코드베이스(백엔드 서비스·스키마) 확인 후 아티팩트로 새 다이어그램 작성. 원본 이미지와 실제 구현의 핵심 차이:
- **5단계 내부 파이프라인은 없음** — [`decompose_skills()`](backend/app/services/llm.py:140) 함수 하나가 프롬프트 1회로 역량+근거를 동시에 추출.
- **출력 계약도 다름** — `tasks|skills|evidence|experience|search_queries`가 아니라 [`SkillProfile`](backend/app/schemas/career.py:102)의 `skills[{name, category, evidence, confirmed}]` 뿐.
- **"출력 형식 검증"은 별도 단계 아님** — OpenAI structured output(`response_format=_SkillsOut`)이 파싱 시점에 스키마 강제.
- **Task 추출로 보이는 부분은 죽은 코드** — STEP 1 `analyze_automation_tasks()`/`automation.diagnose()`는 백엔드에 남아있지만 [`frontend/src/api/client.ts`](frontend/src/api/client.ts)에서 호출 안 됨 (최근 커밋 "STEP 1 위험도 진단 제거"와 일치).

---

**사용자**: 클로드 코드에선 이미지 못 만들어?

**어시스턴트**: Claude Code엔 래스터 이미지 생성 도구가 없음. SVG/HTML 아티팩트로 다이어그램만 가능, PNG/JPG 신규 생성은 불가.

---

**사용자**: 내가 보낸 이미지를 우리 프로젝트에 맞게 수정 하기 위한 프롬프트를 알려줘

**어시스턴트**: 원본과 같은 2단 레이아웃(사용자 흐름 4단계 / 내부 처리 3단계 / 출력 계약 박스 / 요약 문구)을 유지하되 실제 구현에 맞춘 인포그래픽 생성 프롬프트를 제공. Task 추출 단계는 죽은 코드라 제외.

전체 프롬프트 내용:
> 아래 내용으로 인포그래픽 다이어그램을 그려줘. 원본과 같은 2단 레이아웃(위: 사용자가 보는 흐름 4단계 가로 배열, 아래: 내부 처리 단계 가로 배열, 그 아래 출력 계약 박스, 맨 아래 요약 문구)을 유지하되 아래 내용으로 교체해줘.
>
> [상단 — 사용자가 보는 흐름] (4개 박스, 화살표로 연결)
> 1. 경험 입력 — 이력서 업로드 또는 설문 6문항 (career_text 생성, LLM 미사용)
> 2. 역량 초안 확인 — skills 목록 표시
> 3. 수정 · 확정 — 사용자가 항목별로 확정(confirmed) 처리
> 4. 검색 단계 전달 — 확정된 역량 프로필을 직무 탐색으로 전달
>
> [하단 — 내부 처리 단계] (3개 박스만, 화살표로 연결 — 5개 아님)
> 1. 입력 조립 — career_text (이력서 원문 또는 설문 답변 조립, LLM 미사용)
> 2. 역량 분해 LLM 호출 — 프롬프트 1회, "전이 가능한 역량 4~6개 + 근거(evidence) 필수" 지시, 강조색으로 표시
> 3. 구조화 출력 파싱 — 스키마(Pydantic) 강제로 형식 오류 자동 차단, 별도 검증 단계 아님
>
> [출력 계약 박스] (녹색 톤)
> skills: [ name, category, evidence, confirmed ]
> ※ tasks·experience·search_queries 필드는 없음
>
> [맨 아래 요약 문구]
> 역량 정리까지 담당 — 직무 추천과 학습 순서는 후속 LLM이 이어받음
>
> 디자인: 원본처럼 깔끔한 플랫 디자인, 파스텔 톤 박스, 화살표로 단계 연결, 한국어 라벨, 내부 처리 단계 중 "역량 분해 LLM 호출" 박스만 강조색(주황/앰버 계열)으로 눈에 띄게.

---

**사용자**: 이 이미지도 우리 코드에 맞게 수정하기 위해 필요한 프롬프트를 알려줘

**어시스턴트**: [backend/app/api/routes/jobs.py](backend/app/api/routes/jobs.py)와 [JobPathChooser.tsx](frontend/src/components/cards/JobPathChooser.tsx) 코드에 맞춰 좌우 2트랙 비교표 프롬프트 작성. 원본의 "정렬 기준"과 "결과" 항목이 실제 판정 로직과 달라 그 부분을 수정.

전체 프롬프트 내용:
> 아래 내용으로 인포그래픽 다이어그램을 그려줘. 원본과 같은 레이아웃(위: 공통 입력 박스 하나, 아래: 좌우 2트랙 비교 표, 각 트랙은 헤더 + 5행 표)을 유지하되 내용은 아래로 교체해줘.
>
> [상단 공통 입력 박스]
> 사용자가 확인·확정한 역량 프로필 (SkillProfile.skills)
>
> [좌측 — 인접 직무 전환형] (파란 계열 헤더, 라벨 "경험을 이어서 전환")
> - 사용자 선택: "현재 경험과 역량은 활용하되, 같은 직무가 아닌 유사·인접 직무를 찾습니다"
> - 검색 범위: 역량 벡터로 유사 공고 폭넓게 검색(top-K의 8배) → 같은 직무명끼리 그룹핑 → LLM이 방향에 맞는 후보 최대 10개 선별
> - 정렬·판정 기준: 공고별로 LLM이 요구역량 대비 부족역량 비율을 판정 — 비율 0.6 이하(요구역량 60% 이상 보유)이고 매칭 역량이 1개 이상이면 인접 직무로 인정
> - 적합도 산출: 역량↔공고 벡터 코사인 유사도를 백분율로 환산
> - 결과: 격차 작은 인접 직무 상위 5건, 같은 직무는 공고 수와 함께 하나로 묶어 표시
>
> [우측 — 교육 후 직무 전환형] (초록 계열 헤더, 라벨 "새 기술을 배워 전환")
> - 사용자 선택: "현재 일과 다른 분야에서 직업교육·자격·도구 학습 후 진입할 직무를 찾습니다"
> - 검색 범위: 검색 순서를 뒤집음 — LLM이 먼저 전이 가능한 새 직무 4~6개를 제안하고, 그다음 그 직무에 실제 훈련과정·채용공고가 있는지 데이터로 검증
> - 정렬·판정 기준: 제안된 직무의 훈련과정 유사도가 0.55 이상이어야 통과(하드 게이트, 배울 곳 없으면 탈락). 채용 유사도 0.55 이상이면 대표 공고 링크 첨부
> - 적합도 산출: 벡터 유사도가 아니라 "전이 비율" — 요구역량 중 이미 이어지는 보유 역량의 비중
> - 결과: 훈련과정으로 검증된 새 직무 상위 5건, 학습이 필요한 역량과 함께 제시
>
> 디자인: 원본처럼 좌우 대칭 표 레이아웃, 좌측 파란 톤·우측 초록 톤 헤더 유지, 한국어 라벨, 각 행 라벨은 회색 배경 태그로 강조.
